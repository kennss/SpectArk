## なぜ SpectArk なのか

Time Machine のように過去の時点へ戻れる仕組みは大好きです。しかし開発者として使うには、
合わない部分がありました。

- **システム全体のバックアップは必要ありません。** Time Machine は OS やアプリ、ライブラリまで
  コピーします。Mac が壊れても、それらは再インストールすれば済みます。再インストールできないものは
  別にあります。いま取り組んでいるソースコードとプロジェクトです。ほかの分野で働く方も同じです。
  編集中の動画、補正中の写真、作業中の Excel ファイルや文書のように、作り直せないのは結局、
  いま手を入れている作業そのものです。
- **定期バックアップには必ず空白があります。** 間隔が長ければ最新のコードを失うおそれがあり、
  短くしてもマーフィーの法則が訪れた瞬間、直近の数分は消えてしまいます。Git も守ってくれるのは
  コミットしたものだけで、コミットとコミットの*あいだ*の作業は守ってくれません。
- **だからこそ、コードの変化に追従するバックアップが必要でした。** 作業中のフォルダを指定すると、
  すべての変更が数秒以内にバックアップされ、戻れる復元ポイントが最大 15 分ごとに残ります。
  スケジュールも空白もありません。このリアルタイム動作こそが、このアプリが存在する理由です。
- **ドライブを丸ごと一台差し出したくもありませんでした。** バックアップ専用のディスクを用意するのは
  無駄に感じました。バックアップをどこに置くかを自分で選び、どのフォルダでも好きな保存先と
  自由に組み合わせられる必要がありました。
- **バックアップが情報漏えいの原因になってはいけません。** バックアップ用のドライブや NAS は
  紛失や盗難に遭うことがあり、平文のバックアップは中のファイルをすべて渡してしまうのと同じです。
  そこで、どのバックアップでもエンドツーエンドの暗号化を有効にできます。パスワードでのみ開けられ、
  非常用に一度だけ表示されるリカバリーキーがあります。暗号化は任意で、既定ではオフです。
  必要ないときは、バックアップは Finder でそのまま開ける普通のファイルとして残ります。

こうして生まれたのが SpectArk です。リアルタイムに、フォルダ単位で、バージョンごとにバックアップし、
必要なら暗号化もします。本当に大切なファイルを守り、その置き場所はユーザー自身が決めます。

## 機能

- **途切れない保護と Time Machine 方式の復元ポイント**: すべての変更が数秒以内にバックアップされ、
  復元ポイントは最大 15 分ごとに残ります。直近 24 時間はすべて、1 か月までは 1 日に 1 つ、
  それ以降は 1 週間に 1 つずつ保持します。変更されたファイルだけをコピーし、どのフォルダが
  変わったかは macOS のファイルシステムジャーナルから取得します。SpectArk が起動していなかった
  間の変更も含まれます。
- **バックアップごとにリアルタイムまたはスケジュール**: フォルダをリアルタイムで監視するか、
  一定の間隔で実行します。
- **複数のソースフォルダ**を、それぞれ好きな保存先と組み合わせられます。
- **ローカルディスクまたは NAS** を保存先にできます。NAS のバックアップは共有フォルダ上の
  ディスクイメージに保存され、タイムラインと復元をアプリからそのまま使えます。保存先は macOS が
  どこにマウントしても自動で見つけます。
- **バックアップディスクの空き容量を守ります**: すべてのバックアップディスクの 5%（または指定した
  容量）を空けておき、不足するとそのディスク上のすべてのバックアップを通して、最も古い復元ポイント
  から削除します。
- **任意の暗号化**: コンテンツ定義チャンキングと重複排除、AES-256-GCM、argon2id で導出した鍵、
  一度だけ表示されるリカバリーキーを使います。既定ではオフです（バックアップは平文のまま閲覧可能）。
- **作り直せるファイルはスキップします**（依存フォルダ、ビルド成果物、キャッシュ）。そのフォルダを
  作ったツールを確実に識別できる場合に限ります。
- **ダッシュボードウインドウとメニューバーのドロップダウン**（リアルタイムの転送速度、空き容量、
  最終バックアップ）を備え、ログイン時に静かに起動します。
- サンドボックスを使わない Developer ID 配布、macOS 14 以降。

## はじめに

1. **+** ボタンで**バックアップを追加します。** 守りたいフォルダと保存先を選びます。保存先は
   どのディスク上のフォルダでも、Finder でマウントした NAS の共有フォルダでも構いません。
   **Realtime**（ファイルが変わるたびにバックアップ）または **Scheduled**（一定の間隔ごと）を選び、
   必要なら暗号化を有効にします。パスワードを設定し、一度だけ表示されるリカバリーキーを必ず
   保存してください。
2. **アクセスを求められたら許可します。** SpectArk がデスクトップ、書類、ダウンロードフォルダを
   初めて読むとき、macOS が許可を求めます。それ以外の保護された場所（ほかのユーザーのフォルダ、
   写真ライブラリなど）をバックアップするには、**システム設定 ▸ プライバシーとセキュリティ ▸
   フルディスクアクセス**で SpectArk をオンにしてから、SpectArk を終了して再度起動してください。
3. **ログイン時に開く**をオンにします（**Settings ▸ General**、またはリアルタイムバックアップ画面の
   案内から）。リアルタイムバックアップは SpectArk が開いている間だけ動作します。ログイン時は
   ウインドウも Dock アイコンも出さずに、メニューバーで静かに起動します。
4. **履歴をどれだけ残すか**を、各バックアップの **⋯ ▸ Settings** で決めます。Automatic
   （Time Machine 方式）、最新の N 個、N 日分、すべて保持から選べます。最大サイズと、バックアップ
   ディスクに空けておく容量（0 = 自動、ディスクの 5%）も指定できます。

## 復元

- **⋯ ▸ Restore…**（またはバックアップを右クリック）: 復元ポイントを選び、戻したいファイルと
  フォルダにチェックを入れて、元の場所または別のフォルダに復元します。同じ名前のファイルが
  すでにある場合の扱いも選べます。暗号化されたバックアップは、復元ポイントを丸ごと、指定した
  フォルダに復元します。
- **最新のバックアップ状態は普通のフォルダです。** ローカルディスク上のバックアップなら、
  保存先カードをクリックすると Finder で開き、ファイルをそのまま取り出せます。

## ビルド

Xcode プロジェクトは [XcodeGen](https://github.com/yonaskolb/XcodeGen) で生成します。

```sh
brew install xcodegen      # 初回のみ
xcodegen generate          # SpectaBackup.xcodeproj を生成
open SpectaBackup.xcodeproj
```

コマンドラインから直接ビルドすることもできます。

```sh
xcodegen generate
xcodebuild -project SpectaBackup.xcodeproj -scheme SpectaBackup -configuration Release build
```

`SpectaBackup.xcodeproj` は生成されるファイルのため git の管理対象外で、`project.yml` が基準です。
プロジェクトとスキームは旧名の `SpectaBackup`（バンドル ID `ai.calidalab.spectabackup`）を
そのまま使っています。名前を変えても、既存のバックアップ、キーチェーン項目、フルディスクアクセスが
そのまま引き継がれるようにするためです。ビルドされるアプリ名は `SpectArk.app` です。リリース
（署名、公証、DMG、Sparkle appcast）は `scripts/release.sh` で作成します。

## データの整合性

バックアップエンジンは、正確さを基準に選んだ macOS の基本機能の上に作られています。
- すべての変更は、ディスクに触れる前に SQLite カタログへ先に記録されます。そのため途中で
  中断されたバックアップは、次のバックアップで修復されます。
- コピーは `fsync` したうえでアトミックな `rename` で配置し、カタログは `F_FULLFSYNC` で
  コミットします。
- コピーしたファイルはすべて元のファイルと照合し、読み取り中に元のファイルが変わっていた場合は
  そのコピーを破棄します。そのため、書きかけのファイルが記録されることはありません。

ただし、互いに整合している必要があるファイル（データベースとその `-wal` ファイルなど）は、
同じ瞬間にまとめてではなく、1 つずつ順番にコピーされます。ソースのスナップショットを使うには
root 権限と、Apple が個別に付与する entitlement が必要です（[TODO.md](TODO.md) を参照）。
バックアップエンジンの設計は [`docs/INCREMENTAL_ENGINE_DESIGN.md`](docs/INCREMENTAL_ENGINE_DESIGN.md)
に、暗号化リポジトリの設計は [`docs/ENCRYPTION_DESIGN.md`](docs/ENCRYPTION_DESIGN.md) に
まとめています。
