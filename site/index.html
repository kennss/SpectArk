Realtime backup

The instant you
hit save.

Point SpectArk at the folder you're working in and that's it — no schedule to pick, no button to press. Only changed files are copied, so editing one file doesn't rescan the whole folder; which folders changed comes from the macOS file-system journal.

  • Changes backed up within seconds — no schedule, no gap
  • Catches up on what changed while SpectArk wasn't running
  • Or run on an interval, per backup — you choose
  • Menu-bar app with live throughput, free space & last backup

Restore points

Go back to
3 p.m. yesterday.

A restore point is kept at most every 15 minutes, another for a state you leave standing, and one whenever you run a backup yourself. Delete or rename a file and the state just before is kept too, so the file comes back under its old name. Old history thins out the way Time Machine's does: everything from the last 24 hours, one a day for a month, one a week after that.

  • Restore single files or whole folders
  • Choose what happens when a file already exists
  • On a local disk, the latest backup is a plain folder — open it in Finder and copy straight out
  • Old history thins itself — nothing to manage

Just what matters. Anywhere you like.

Any folder.
Any drive.

No whole-system copy, no drive dedicated to backups. Pick the folders you can't reinstall and pair each with any destination — an external SSD, a spare partition, or a NAS. A NAS backup keeps its full timeline too, and restores right in the app.

  • Several source folders, each paired with its own destination
  • Finds the share again even when macOS mounts it under another name
  • Skips rebuildable files — node_modules, build outputs, caches
  • Picks the right storage format for each destination

Never stops for a full disk

Clears the oldest
first, on its own.

Every backup disk fills up eventually, and a backup that stops then protects nothing. SpectArk keeps 5% of the disk free, and when it runs short, deletes the disk's oldest restore points first — across all the backups on it, the way Time Machine does.

  • Oldest first, whichever backup it belongs to
  • Never deletes a backup's newest restore point
  • Set the free space to keep yourself
  • A backup stopped for lack of space makes room and carries on

Optional end-to-end encryption

The backup shouldn't
become the leak.

A backup drive or NAS can be lost or stolen — and a plaintext copy hands over every file on it. So any backup can be encrypted end-to-end, unlocked only by your password, with a one-time recovery key as a fallback. It's off by default: when you don't need it, backups stay plain files you can open in Finder.

  • AES-256-GCM with argon2id-derived keys
  • Content-defined chunking + dedup — encrypted, still efficient
  • One-time recovery key so you're never locked out
  • Opt-in per backup — plaintext stays browsable when you don't need it

Safe before anything else

Every change is logged in the catalog before it touches the disk, so an interrupted pass is repaired on the next one. Copies are fsynced and put in place with an atomic rename, and the catalog commits with F_FULLFSYNC. Every copy is checked against its source and dropped if the file changed while it was read — a backup never holds a half-written file.
